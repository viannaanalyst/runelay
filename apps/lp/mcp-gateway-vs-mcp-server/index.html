How they fit together

A gateway does not replace MCP servers, it is built on them. To your agent it is one MCP server. Behind it, it acts as a client to every upstream server, OpenAPI spec or local process you connect, and keeps their credentials.

  • search_toolsFind a tool across every connected account.
  • call_tool · executeCall one tool, or chain several in sandboxed JavaScript.
  • read_memoryShared notes every agent can read and write.
  • read_skillYour SKILL.md folders, served on demand.

One MCP server is enough when

  • You use one agent and one or two apps.
  • A few thousand extra tokens at connect are fine.
  • Logging in again when you switch tools is no big deal.

You need a gateway when

  • Several agents should see the same accounts.
  • You connect many apps and context is tight.
  • You want one key per agent and one audit log.
  • Memory and skills should travel between agents.

Questions

Is an MCP gateway also an MCP server?

Yes. It speaks MCP to your agents and acts as an MCP client to the servers behind it.

Does a gateway add latency?

Barely. A tool call through runelay takes 6.6 ms median on localhost, on top of the upstream server’s own time.

Can a gateway run local stdio MCP servers?

Yes. runelay runs local MCP servers next to remote ones and OpenAPI specs.

Do I have to change my agents?

No. Point them at one endpoint, /v1/mcp, with their own key. runelay connect does it for you.
